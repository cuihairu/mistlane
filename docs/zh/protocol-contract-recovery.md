# 协议契约恢复

状态：2026-11-21 从已提交的 game-fogs schema 二进制 `game-fogs/game/proto/sproto.spb`（game-fogs commit `37b640a`）恢复。本页恢复的是旧业务协议的**定义**，不声称原始生成流程；原始文本源、生成脚本与正式客户端绑定仍缺失。英文页：[Protocol contract recovery](../protocol-contract-recovery.md)；恢复产物：`contracts/fogs-sproto-schema.txt`；复现工具：`tools/sproto_dump.c`。

## 恢复了什么

已提交的编译 schema 解码为一份完整的业务协议契约：

- **646 个 RPC 协议**，各带数字编号（tag）、请求类型与响应类型（服务端→客户端推送无请求类型；客户端→服务端单向无响应类型）。
- **1421 个数据类型**——请求/响应体以及被引用的 struct、数组（`*Type`）与 map（`*Type[key]`）类型。
- **4245 个字段**，各带字段编号（tag）与类型。

示例（`contracts/fogs-sproto-schema.txt`）：

```
AC_Broadcast.request
	tp (0) integer
	actid (1) integer
	edTime (2) integer
...
OmAuth (30001) request:OmAuth.request response:OmAuth.response
```

## 方法

`.spb` 是编译后的 sproto schema（格式由 `game-fogs/3rd/sproto/sproto.c` 定义）。用 vendored sproto 解码器经一个小型 dumper（`tools/sproto_dump.c`，调用 `sproto_create` + `sproto_dump`）解码；不涉及 Lua 解释器或宿主层。dump 是参考解码器自身的输出，因此是对编译 schema 的权威表示。

## 验证

- **名称→编号交叉核对：** schema 中 646 个协议编号与 `game-fogs/game/proto/Protocol.lua` 完全一致——0 缺失、0 多余、0 不匹配。`Protocol.lua` 是独立生成的产物（`--Generated by sprotodump. DO NOT EDIT!`），故这是独立的交叉一致检查。
- **类型引用：** 0 个未解析的请求/响应类型引用；0 个未解析的 struct 字段类型引用（剥离 `*` 数组与 `[key]` map 标记后）；所有字段解析为已声明类型或原语（`integer`、`boolean`、`string`、`double`）。
- **形态：** 646 协议 / 1421 类型 / 4245 字段；69 个协议无请求类型（推送），151 个无响应类型；638 个字段为数组类型，152 个为 map 键控。

## 来源与缺失项

- **产物来源：** `sproto.spb` 与 `Protocol.lua` **已提交**到 game-fogs `37b640a`；`game/Data/Data.lua` 在启动时把该二进制装载进 sproto loader 槽。`Protocol.lua` 头部标明其生成器为 **`sprotodump`**。
- **缺失——原始文本源：** game-fogs 中不存在任何 `.sproto` 文本文件；schema 仅以编译形式存续。
- **缺失——生成脚本：** game-fogs 中不存在运行 `sprotodump`/sproto 编译器的构建规则或脚本；生成工具已识别，但调用它的构建步骤缺失。
- **缺失——正式客户端绑定：** 客户端侧生成的协议绑定属于独立客户端代码库，不在恢复 schema 的服务端仓库内。

## 范围警示

恢复的 schema 是**编译产物**，不是原始生成流程。它携带 RPC 名称、编号、请求/响应类型与字段布局，但不携带原始文本源的注释、布局，也不携带产生绑定的构建步骤。按 todo 账本（`todo.md`），这被视为定义恢复，而非完整生成管线；参见第 72 项与 [玩家、场景与跨服模型](./player-scene-model.md#协议、方法定义与抽象前置条件)。
